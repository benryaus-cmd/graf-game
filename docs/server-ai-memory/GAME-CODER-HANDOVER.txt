Spatial player semantics:
- world_snapshot.players contains only nearby/renderable players.
- world_snapshot.playerDirectory contains the lightweight room-wide identity directory.
- player_directory_joined / player_directory_left update the ONLINE/player/profile directory only.
- player_joined means spawn/show a nearby 3D avatar.
- player_left with spatial:true or reason spatial_out_of_range means remove/hide that remote 3D avatar ONLY. Do NOT mark that person offline; keep them in playerDirectory.

- player_state continues to update nearby avatars normally.

- upsertPieces
- removePieceIds
- upsertArtworks
- removeArtworkIds
- upsertStrokes
- removeStrokeIds

CRITICAL: spatial removal means "unload because it is far away", NOT "authoritatively delete forever". Do not feed spatial removeStrokeIds through the current rejection/tombstone path in PaintSync.removeStrokeIds/rejectPiece, because that would prevent the same art loading again when the player walks back into the area. Add a separate temporary/unload path for spatial streaming. Same principle for pieces/artwork: unload render/state cleanly but allow later upsert to restore them.

Do not full-resnapshot/rebuild the whole city for every spatial delta. Apply deltas in batches. When strokes are removed/added, collect affected walls and rebuild each affected wall at most once per received delta.

Keep current local-first painting. The local painter must never wait for server round trips to see their own paint.
