5. SPATIAL PERSISTENT WORLD DELTAS
==================================================

SERVER -> CLIENT
{
  "type": "spatial_world_delta",
  "reason": "cell_changed|revision|live_stroke_bootstrap|...",
  "revision": 123,
  "sequence": 456,
  "serverTime": 1234567890,
  "upsertPieces": [ /* public graffiti pieces */ ],
  "removePieceIds": ["piece-id"],
  "upsertArtworks": [ /* artwork objects */ ],
  "removeArtworkIds": ["artwork-id"],
  "upsertStrokes": [ /* full stroke objects */ ],
  "removeStrokeIds": ["stroke-id"]
}

CRITICAL: spatial remove IDs mean "not currently relevant / unloaded from this client" unless a normal authoritative delete event says it was deleted.

DO NOT feed spatial removePieceIds/removeStrokeIds/removeArtworkIds through permanent delete/tombstone logic.
They must be temporary unloads so entities can reappear via a later upsert when the player walks back.

Normal authoritative deletion events remain permanent:
- piece_removed
- artwork_removed
- stroke_gesture_undone (specific stroke IDs actually removed from authoritative piece)

Recommended implementation:
- keep spatial presence/cache state separate from authoritative deletion/tombstone state.
- upserts add/update nearby entities.
- spatial removals unmount/release GPU/canvas resources, but must allow a later upsert with the same ID.

7. EXACT FULL-GESTURE UNDO / REDO CONTRACT
==================================================

Capability: stroke_undo_redo
Server limit: 2 full gestures.
Undo is allowed only on own active, non-flattened piece.
Edit history is transient and is NOT persisted across server restart.
Starting a fresh finger gesture clears redo history.

GESTURE GROUPING RULE:
The server groups stroke segments by ID prefix before the final numeric .suffix.
Examples:
- abc123.0
- abc123.1
- abc123.2
all equal gestureId "abc123".
A stroke ID with no final .<number> is its own gesture ID.

CLIENT -> SERVER undo
{
  "type": "stroke_undo",
  "pieceId": "piece-id"
}

SERVER -> ROOM/RELEVANT CLIENTS
{
  "type": "stroke_gesture_undone",
  "pieceId": "piece-id",
  "gestureId": "abc123",
  "strokeIds": ["abc123.0", "abc123.1"],
  "revision": 500,
  "sequence": 900
}

SERVER -> REQUESTING CLIENT after undo
{
  "type": "stroke_history_state",
  "pieceId": "piece-id",
  "canUndo": true,
  "canRedo": true,
  "undoDepth": 1,
  "redoDepth": 1,
  "limit": 2,
  "serverTime": 1234567890
}

CLIENT -> SERVER redo
{
  "type": "stroke_redo",
  "pieceId": "piece-id"
}

SERVER -> ROOM/RELEVANT CLIENTS
{
  "type": "stroke_gesture_redone",
  "pieceId": "piece-id",
  "gestureId": "abc123",
  "strokes": [ /* complete authoritative stroke objects restored by server */ ],
  "revision": 501,
  "sequence": 901
}

SERVER -> REQUESTING CLIENT then sends stroke_history_state again.

Known errors:
{ "type":"error", "code":"stroke_undo_unavailable" }
{ "type":"error", "code":"stroke_redo_unavailable" }
{ "type":"error", "code":"stroke_undo_limit", "limit":2 }
{ "type":"error", "code":"nothing_to_undo" }
{ "type":"error", "code":"nothing_to_redo" }

CLIENT WIRING:
- Add UNDO and REDO beside zoom controls.
- Apply stroke_gesture_undone by removing the supplied strokeIds and rebuilding only affected wall(s), not full world.
- Apply stroke_gesture_redone from the supplied full strokes.
- Buttons should use stroke_history_state; never fake optimistic availability beyond server state.
- Undo/redo applies to the currently active own piece only.
