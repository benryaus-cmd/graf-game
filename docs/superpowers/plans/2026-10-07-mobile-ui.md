# GraffCiti Mobile UI Implementation Plan

> **For agentic workers:** Execute inline with superpowers:executing-plans, then one independent final review.

**Goal:** Polished mobile graffiti UI around the existing working game.
**Architecture:** Preserve game callbacks and infrastructure. Introduce one reusable sheet and UI-only state coordination; scope CSS to the game container.
**Tech Stack:** Existing React, TypeScript, CSS, Vite and Node test runner. No added product dependencies.
**Spec:** `docs/mobile-ui-design.md`

## Global Constraints
- Mobile portrait inside a shorter Aippy game frame is the priority.
- No game/network/server redesign. Preserve ZIP infrastructure bytes after reconciliation.
- Primary touch targets 44px; game fills available parent; sheet headers remain reachable.
- Keep actual server prices, ownership, permissions and timer semantics.

## Review Focus
- Short embedded frames and rotated shells must not clip headers/actions.
- Opening/closing any sheet must not clear/finalize a piece or switch sessions.
- Done calls exit, Edit Again calls enter, and finish retains title arguments.
- Chat arrival must preserve reading position and count new messages while closed.
- Selecting a player/artwork must not reopen a locally dismissed sheet on every state update.
